# 超星接入：边界与抓包验证

## 一、先说边界

这个适配器**只做两件事**：

1. 用你自己的账号登录超星
2. 拉取你账号下的课程列表

它**不做**，而且不会做：

| 不做 | 对应 MoocPass 里的什么 |
| --- | --- |
| 视频播放进度上报 / 挂机 | `ChaoxingPlatformAdapter` 的进度上报逻辑（85KB 的大部分） |
| 章节任务点提交 | 同上 |
| 试卷 / 作业答题 | `solver/AiQuestionSolver`、`answer/QuestionAnswerService` |
| 签到 | — |
| 破解验证码 | `CaptchaDecoder/`（Python + ddddocr，打超星 9010 安全验证码） |
| 破解字体混淆 | `CxSecretDecoder` + `cxsecret_map.json` + `cxsecret_reference.ttf` |
| 代理换 IP 躲风控 | `MOOC_PROXY_*` |

**遇到验证码我们直接失败，不绕过。** `ChaoxingAdapter.login()` 里检测到验证码会抛异常，
提示用户改用 Cookie 方式。即使目的只是读自己的课表，也不去拆平台专门部署的防护措施
——这是这个项目和 MoocPass 的根本区别，不是程度区别。

## 二、为什么我没有直接把超星接口写死

因为**超星各校部署版本不一样**。有的学校用 `i.chaoxing.com`（公有云），
有的是学校定制/自建域名，登录页的 JS 也可能不同版本。我凭记忆写死的端点，
你大概率要花几个小时调试一个根本不存在的接口。

所以代码里凡是标 `【待确认】` 的地方都是**结构性占位**：
请求流程写好了（`java.net.http.HttpClient` + `CookieManager`），
你只需要抓包确认具体字段，然后改那三处。

## 三、抓包步骤

用**浏览器**抓就够了，不需要装 Charles / mitmproxy 那种要装证书的工具。

### 准备

1. Chrome 或 Edge 打开 `https://i.chaoxing.com`
2. `F12` → **Network** 面板
3. 勾上 **Preserve log**（保留日志），过滤选 **Fetch/XHR**
4. 清空一下，然后**登录**

### 要记录的三件事

#### 记录 A：登录请求

在 Network 里找登录请求（通常是 `fanyalogin` 或 `login`）。

点开它，记下：

- **Request URL** —— 完整地址
- **Method** —— POST 还是 GET
- **Payload / Form Data** —— 请求体里有哪些字段，各自的**值长什么样**

⚠️ **重点看 `password` 字段**。这对应代码里的 `【待确认 2】`：

- 如果是你自己输入的**明文密码** → 那么 `ChaoxingAdapter.login()` 现在就是对的，不用改
- 如果是一串 **32 或 64 位十六进制**（如 `a3f1...`）→ 说明前端 JS 先做了 AES 加密。
  这时你需要：在 Sources 面板找到加密函数，用 Java 复现它。
  **注意**：这是"让自己的登录请求能被接受"，不是绕过风控 —— 如实实现即可。

#### 记录 B：登录响应

看 Response，记下：

- 是不是 JSON？
- `status` 字段叫什么（`status`？`result`？）
- 成功时是什么值（`true`？`1`？）
- 失败时的消息字段叫什么

这对应 `【待确认 3】`。

#### 记录 C：课程列表请求

登录后进入「我学的课」或课程列表页。

找到返回课程列表的那个请求，记下：

- **Request URL**（连同 query string）
- **Response** —— 完整 JSON。**存成文件**，等下要对照代码看。

### 填进配置

改 `server/src/main/resources/application.yml`：

```yaml
campus:
  chaoxing:
    enabled: true
    login-url: <记录 A 的 URL>
    course-list-url: <记录 C 的 URL>
```

### 对照抽取逻辑

打开 `ChaoxingAdapter.collectCourses()`，它做的事是：

> 递归遍历 JSON，凡是**同时有 `name` 且有 `courseid` 或 `clazzid`** 的对象，就算一门课。

这个写法是**故意不硬编码 JSON 路径**的 —— 超星各校响应结构差异大。
但你需要拿记录 C 存下的 JSON 核对一遍：

- 课程名在 `name` 字段吗？如果是 `courseName` / `title`，改 `text(node, "name")` 附近
- 课程 id 是 `courseid` 吗？可能是 `courseId` / `id`
- 教师是 `teacher` 吗？

改完跑一次 `POST /api/sync/chaoxing`，看同步任务返回的 `courseCount` 对不对。

## 四、验证清单

按顺序过一遍，每步都要看到预期结果：

- [ ] `POST /api/auth/login` 拿到 token（mock 模式传 `{"openid":"demo"}`）
- [ ] `POST /api/bindings` 传超星账号密码，返回 `{ok: true}`
      —— 如果返回验证码提示，说明这条路对，改用 Cookie 模式
- [ ] `POST /api/sync/chaoxing` 立刻返回 taskId（**必须 < 15 秒**，否则云托管会超时）
- [ ] `GET /api/sync/tasks/{taskId}` 轮询到 `SUCCESS`，`courseCount` 和你实际选课数一致
- [ ] `GET /api/courses` 返回课程列表
- [ ] 小程序「课表」页能显示（如果 `courseCount > 0` 但课表是空的，看下一节）

## 五、绕不开的现实：超星给不了精确课表

**超星的课程列表接口通常不返回"周几第几节、哪个教室"。** 这是接口本身的设计，
不是我实现得不好。所以 `fetch()` 里 `sessions` 大概率是空列表，
它会返回一句提示而不是编造数据。

三条路，按推荐顺序：

### 路 1（强烈推荐）：从教务系统取课表

你学校的**课表**其实在教务系统里，超星只是给你放课程视频的地方。

**已知情况**：你的课表来自「移动教务」，地址是 `<教务系统地址>`（**IP 直连，不是域名**），
界面是自研/私有部署的（不是正方、不是强智、不是 URP）。校区是<校区>。

这意味着两件事：

**好消息**：私有部署的系统通常接口更朴素，没有超星那种字体混淆、参数签名之类的防护，
抓包 → 复现的难度低得多。

**坏消息（要先确认）**：⚠️ **这个 IP 在校外能访问吗？**

这决定了整个架构可不可行：

- 如果**校内外都能访问**（公网 IP）→ 云托管后端可以直连，走标准流程
- 如果**只有校园网/VPN 能访问** → 云托管**根本连不上**，因为它的出口在腾讯云机房。
  这时只能：
  - **方案 A**：后端部署在校园网内的一台机器上（宿舍/实验室的树莓派、旧笔记本），
    再用内网穿透（frp / Cloudflare Tunnel）暴露出去 —— 但小程序要求 HTTPS，
    而 `callContainer` 又只能指向云托管，这条路和云托管冲突，要走 `wx.request` + 域名备案
  - **方案 B（务实）**：放弃自动同步，**用手动导入**。课表一学期就变几次，
    粘一次用一学期，成本远低于维护一套穿透

**先做这个测试**：把手机流量打开（不要连校园 WiFi），浏览器访问 `http://<教务系统地址>`，
看能不能打开登录页。这一步的答案决定后面所有事。

### 写 `JwxtAdapter` 的流程

1. 加 `Capability`（`SCHEDULE`、`GRADE` 都已经在枚举里了）
2. 写一个 `@Component` 实现 `CampusAdapter`，参考 `ChaoxingAdapter` 的结构
   （`java.net.http.HttpClient` + `CookieManager` + JSON 树遍历）
3. 抓包思路和第三节完全一样，只是目标换成教务系统：
   找登录请求 → 找课表请求 → 记录响应结构
4. 教务系统返回的课表通常是「周几 + 第几节 + 周次范围 + 教室」的 JSON 或 HTML 表格，
   比超星友好得多。用 `WeekTextParser` 解析时间文本
5. 注册表会自动发现它，不用改任何其他代码

> 💡 抓包时注意：教务系统的课表接口往往带 `semester` / `week` 之类的查询参数，
> 记得把**整个 query string** 记下来。

### 路 2（现在就能用）：手动导入

`ManualAdapter` 已经能用了，零风控风险。在「我的 → 服务绑定中心 → 手动导入课表」里，
把课表按行粘进去：

```
高等数学,张老师,周一,1-2节,1-16周,教三201
线性代数,李老师,周三,3-4节,1-16周(单),教二105
大学物理,王老师,周五,5-6节,1-8周,实验楼B302
```

**建议先用这条路把整个界面跑通**，再回头啃接口。后端启动时已经灌了一份同样的
演示课表，所以你现在打开小程序就能看到课表长什么样。

### 路 3：让用户自己填一次，以后从平台补

混合方案：课表用路 2 导入一次，课程详情（教师、封面）从超星补。

## 六、三个已知坑

### 1. Cookie 会过期

Cookie 模式的失效速度取决于超星。过期后同步会失败并提示「Cookie 已过期，请重新绑定」。
`verify()` 会在绑定时就发现这个问题。

### 2. 云托管的出口 IP 是动态的

微信官方文档明确写了：**「云托管服务本身不具有固定的公网出口 IP，而是动态变化的」**，
而且**「不支持用来部署数据库/Redis 等有状态服务」**。

对你的影响：超星可能对来自腾讯云数据中心的 IP 做风控。如果出现莫名的登录失败或
「操作过于频繁」，先怀疑这个。

对策：
- 减少登录次数（Cookie 缓存、状态落库、别每次打开页面都登录）
- 绑定成功后只做定时同步，别做高频轮询
- 真不行就退回手动导入

### 3. 不要在处理请求里同步抓超星

`CallContainer` 超时 **15 秒**，抓超星大概率超。所以整个同步链路已经是异步的
（`SyncService` + `sync_task` 表 + 轮询）。别"优化"成同步调用。

## 七、如果你决定不接超星

完全可以。把 `campus.chaoxing.enabled` 保持 `false`，
超星卡片会显示「暂未开放」，其他功能不受影响。

然后写一个教务系统的 `JwxtAdapter` —— 加平台的完整流程见
[`architecture.md`](architecture.md) 第六节，一共五步。
