# 发布微信小程序：完整流程

## 零、先说清楚哪部分我不能替你做

**我不能替你发布。** 这不是技术问题，是身份和法律问题：

| 步骤 | 为什么必须你本人 |
| --- | --- |
| 注册小程序账号 | 要你的**身份证 + 人脸识别**（或企业的营业执照 + 对公账户打款验证） |
| 登录微信开发者工具 | 要**你本人微信扫码**，二维码只在你手机上 |
| 小程序 ICP 备案 | 要你的主体信息、负责人身份证、手写签名 |
| 提交审核 | 审核通过后，**你**是内容的责任主体 |

所以任何"我直接帮你发"的说法都是不成立的 —— 中间那几步物理上就在你手机上。

**我能做、也已经做的**：把代码、配置、构建产物、部署脚本全部准备好，让你剩下的部分只有
"注册 → 扫码 → 点上传 → 点提交"。这份文档就是那份操作手册。

预计你自己动手的总时间：**注册 30 分钟 + 备案等 1～20 个工作日 + 上传审核 1～7 天**。

## 一、先决定两件事（决定后面全部流程）

### 决定 1：个人主体 还是 企业/组织主体？

|  | 个人主体 | 企业/组织主体 |
| --- | --- | --- |
| 注册材料 | 身份证 + 手机号 + 邮箱 | 营业执照/事业单位法人证 + 对公账户 |
| 可选类目 | **受限** | 宽 |
| 微信支付 | ❌ 开不了 | ✅ |
| 参考截图里那个"投喂奶娃"打赏 | ❌ 做不了 | ✅ |
| 小程序备案 | 需要 | 需要 |
| 审核严格度 | 略严 | 正常 |

**对校园工具类，个人主体够用。** 代价就是打赏功能和部分类目。

> 如果你只是想先跑起来给自己和同学用，个人主体是最快的路。

### 决定 2：类目报什么

**推荐：`工具` → `日历`，备选 `工具` → `信息查询`。两者对个人主体都无资质要求。**

个人主体在「工具」下**实际可选**的子类只有这些（官方类目页原文逐个核对过）：

> 记账、**日历**、天气、办公、图片处理、计算器、报价/比价、**信息查询**、
> 预约/报名、健康管理、备忘录

⚠️ **没有「效率」这个子类。** 网上很多攻略（包括本文档的早期版本）写的"工具-效率"是错的，
个人主体根本选不到，别照抄。

**「日历」最贴切** —— 这个 App 的主体就是按周展示日程（"周"课表 + 周次切换），
`工具-日历` 的类目适用范围原文是"适用于提供日历相关服务"，完全对得上。

**关于「教育服务」——本文档早期版本这里也说错了：**

原文写"教育类目个人主体直接过不了"。核对官方类目页后，准确说法是：
个人主体**确实开放了**教育服务，但**只有一个子类「教育信息展示」**，
且备注明确写着"不支持提供教育视频播放/直播、课程产品销售等服务"。

所以结论没变（**仍然建议报工具类**），但理由要改对：
不是"报不了"，而是**报教育类目会让审核拿教育领域的标准来看你**，
而本项目既没有资质、也不做教学内容 —— 报 `工具-日历` 定位最干净、最不容易被追问资质。

> 官方依据：[小程序开放的服务类目](https://developers.weixin.qq.com/miniprogram/product/material/)
> （页面很长，找「个人主体小程序开放的服务类目」那一节）

### 决定 3：名称 ★ 最容易反复被驳的一步

**先看长度硬性要求：名称 4~30 个字符（1 个中文 = 2 个字符），过短过长都提交不了。**
所以中文名最少要 **2 个字**、最多 15 个字。`小粥历` = 3 个中文 = 6 字符，通过。

**不要在小程序名称里放学校名字。** 含"XX大学/学院"→ 需要学校授权书，个人主体**必被驳回**。

但只避开学校名**远远不够**。备案阶段对个人主体名称有三条硬约束，必须**同时**满足：

| # | 约束 | 触发的词 |
| --- | --- | --- |
| 1 | 名称要**符合个人主体性质** | `公司` `集团` `中心` `平台` `商城` `商贸` 等企业/单位名义与经营性字样 |
| 2 | 不涉**前置/专项审批领域** | `新闻` `金融` `宗教` `医疗器械` `网约车` `校外培训` 等；教育语义也要尽量弱化 |
| 3 | 名称要与**服务内容、备案备注有关联** | 纯自造词（看不出用途）会被判"无关联" |

> 官方口径（微信小程序运营专员）：
> 个人主体小程序的名称应符合个人主体性质，不能涉及企业/单位名义、前置/专项审批相关领域、
> 国家公共事务等关键字，不得超出个人经营范围。
> —— [微信开放社区](https://developers.weixin.qq.com/community/minihome/doc/000e608829cf300a5be3fe27261000)

**这三条是一个三角，单满足任一条都会挂**，本项目的真实经历就是三步都踩了一遍：

| 用过/候选的名字 | 撞的是哪条 | 结果 |
| --- | --- | --- |
| `校园盒子` | 约束 1 —— "校园"+"盒子"被认为是机构/教育性质 | 被电话要求提供**学校证明文件** |
| `粥粥源` | 约束 3 —— 与服务内容、备案备注无任何关联 | 备案驳回：「名称、服务内容、备注三者无关联」 |

**最终采用：`小粥历`。** 它的构造值得记下来，因为这正是三条约束的交集：

- **"粥" 与 "周" 同音** —— 指向"周 / 课表"，承担与服务内容的**关联性**（约束 3）
- **"历"** —— 日程、历法之意，进一步坐实"看日程安排"这个用途
- **"小" + 自造搭配** —— 一眼是个人起的名，不像机构品牌，且不含企业/领域/经营范围词（约束 1、2 全避开）

> **给新对话的提醒**：改名前先拿上面三条约束逐个过一遍。名字一旦备案通过，后续变更要走变更流程。
> 名称审核是独立的一道，和类目审核分开，被驳了可以改名重申，**不限次数**。

## 二、注册小程序账号

1. 打开 https://mp.weixin.qq.com → 右上角「立即注册」→ 选「小程序」
2. 填一个**没注册过公众号/小程序的邮箱**（QQ 邮箱最方便）
3. 去邮箱点激活链接
4. 选主体类型：
   - **个人**：填身份证 + 手机号 → 用**本人微信**扫码做人脸核验
   - **企业**：填营业执照 → 对公账户打款验证（几分钱）或法人扫脸
5. 注册完成后，在 **设置 → 基本设置** 里能看到 **AppID**，把它记下来

> AppID 形如 `wx1234567890abcdef`。这个填到 `miniprogram/project.config.json` 的 `appid` 字段。

## 三、小程序 ICP 备案（必须，不能跳过）

**2023 年 9 月起，新注册的小程序必须完成备案才能发布。** 没有备案，代码传上去了也没法提交审核。

1. mp 后台 → **设置 → 基本设置 → 小程序备案** → 开始备案
2. 填写：
   - 主体信息（自动带入注册时的）
   - **服务内容类型**：选「工具类」→ 最贴近的是「日历」，备选「信息查询」（见决定 2）
   - 负责人信息 + 身份证正反面 + **手写签名照**
   - 应急联系人
3. 提交后：微信初审（1～3 天）→ 提交通信管理局（1～20 个工作日，各省不同）
4. 通过后会拿到备案号，需在小程序内可查（一般放在「关于」页）

> **注意**：备案要求服务内容与实际功能一致。备案写"效率工具"但小程序里全是教育内容，
> 复查时可能被注销备案。

### 3.1 备案备注（必填）★ 直接粘贴

驳回理由里的"小程序名称、服务内容、**备注**三者无关联"，指的就是这个字段。它要同时做三件事：
说明**用途**、坐实**个人性质**、呼应**名字里的"粥/周"**。照下面这段抄：

```text
小粥历（名称取意"每周的日程"，"粥"与"周"谐音）是一款个人自用的信息查询工具。
主要功能：用户在工具内填入本人的学校账号后，可以查看自己的课堂安排（周课表）与
其他本人信息；不填写账号时可查看一份标注清楚的示例课表。
本小程序仅以只读方式查询上述信息，不修改、不上传任何平台记录，不提供在线教学、
课程学习、培训或任何经营性服务。开发者是一名学生，本工具为个人学习实践作品，
不做商业运营，不向用户收取费用，不涉及任何企业或单位主体业务。
```

**为什么这么写**（每一句都在挡一个驳回理由）：

| 句子 | 挡掉什么 |
| --- | --- |
| `"粥"与"周"谐音 … 查看自己的课堂安排` | 约束 3 —— 把名字和服务内容的关联**明写出来**，不让审核员自己猜 |
| `仅以只读方式查询 … 不修改、不上传` | 挡住"这工具是不是在改学校系统数据"的疑虑 |
| `不提供在线教学、课程学习、培训` | 挡住往"教育/校外培训"领域归类 |
| `个人学习实践作品，不做商业运营，不向用户收取费用` | 约束 1 —— 坐实个人性质、非经营性 |
| `不涉及任何企业或单位主体业务` | 正对驳回原文的"不能涉及企业或单位名义" |

> ⚠️ **文案里绝对不要出现的词**：`校园` `学校信息服务` `教务系统` `教育` `平台` `聚合`。
> 尤其 `校园` —— 这个词就是这次被电话要求补学校证明的触发点之一。
> 描述用途时用"本人的课堂安排 / 本人信息"这类**归属于用户个人**的说法。

### 3.2 小程序简介（mp 后台「基本设置」里填的）

和备案备注口径**必须一致**，不要这边写"个人工具"、那边写"校园信息聚合"。用这段：

```text
小粥历是一款个人自用的信息查询工具，用于查看本人录入的课堂安排（周课表）等个人信息。
开发者个人制作，只读查询，不做任何修改，不提供教学、培训或经营性服务。
```

## 五、部署后端到微信云托管

**这一步必须在"上传代码"之前做完**，否则审核时小程序拿不到数据。

完整步骤见 [`deploy-cloudrun.md`](deploy-cloudrun.md)。关键几点：

```powershell
# 打包（在 campus-mini 目录下）
Compress-Archive -Path server\build.gradle, server\settings.gradle, server\Dockerfile, server\src `
                 -DestinationPath server.zip -Force
```

然后云托管控制台 → 服务 `campus-api` → 新建版本 → 上传 `server.zip` → 部署。

**部署后必做的三件事**：

1. **环境变量 `CAMPUS_WECHAT_MOCK_ENABLED=false`**
   ⚠️ 不关掉的话，任何人 POST 一个 `{"openid":"别人的openid"}` 就能拿到那个人的 token ——
   这是**严重安全漏洞**。
2. **最小实例副本设为 1** —— 否则异步同步任务会被缩容杀掉。
3. 服务日志里核对云托管注入 openid 的**请求头名字**，不是 `x-wx-openid` 就改
   `CAMPUS_WECHAT_OPENID_HEADER`。

部署好了以后，改 `miniprogram/utils/api.js`：

```js
const USE_CLOUD = true;
const CLOUD_ENV = '你的环境ID';
const CLOUD_SERVICE = 'campus-api';
```

## 十、⚠️ 这类小程序的高危陷阱

**这一节是本文档最重要的部分。** 校园信息聚合类小程序有特定的踩坑点：

### 陷阱 1：审核员看不到内容 → 被判"功能不完整"

小程序靠微信 openid 登录，**没法给审核员一个"测试账号"** —— 他打开就是新用户，
如果新用户看到的是空白页，大概率被驳回。

**✅ 这个坑已经在代码里修好了**（方案 A）：

用户**一条课表数据都没有**时，后端会返回一份演示课表，并在响应里带 `demo: true`；
前端据此显示一条黄色横幅：「这是示例数据 —— 你还没绑定学校平台，绑定后自动换成你自己的」。

- 审核员一打开就有内容 → 不会因"空壳"被判功能不完整
- 真实用户不会被误导 → 横幅明确说明是示例

实现见 `schedule/DemoScheduleProvider.java` 和 `ScheduleService` 的 `shouldUseDemo()`。
已实测三个场景：

| 场景 | `demo` 标记 | 看到的课表 |
| --- | --- | --- |
| 全新用户（未绑定） | `true` | 示例课表 + 横幅 |
| 用户绑定自己的账号后 | `false` | 只剩他自己的课 |
| 演示账号 `demo` | `false` | 数据库里的真实数据 |

如果你想关掉这个行为（比如担心被误认为在误导用户），把
`campus.demo-data` 设为 `false` —— 但那样审核被驳回的概率会明显上升。

**备选方案 B**：在审核备注里详细说明"需绑定校园账号后才能看到课表，这是设计如此"，
并上传截图。成功率低于 A，但不需要任何代码改动。

### 陷阱 2：名称/简介暗示学校官方或机构性质

- 名称含学校名 → 需要授权书
- 名称含"**校园**"→ 被判机构/教育性质，会被电话要求补**学校证明文件**（本项目实际踩过）
- 简介写"XX大学官方课表" → 被驳回，甚至被学校投诉
- ✅ 正确做法：用 `小粥历` 这类**自造但能指向用途**的名 + 简介和备案备注统一写
  "个人自用、只读查询本人信息"（完整文案见第三节的 **3.1 备案备注** 和 **3.2 小程序简介**）

### 陷阱 3：用户隐私保护指引（强制）

**2023 年 9 月起，小程序必须在 mp 后台配置《用户隐私保护指引》**，
否则调用涉及用户信息的接口会被拦截。

你这个项目**收集了什么**：
- 微信 openid（用于识别用户）
- 你学校的账号密码（用于登录教务系统，AES-GCM 加密存储）

后台配置路径：**设置 → 服务内容声明 → 用户隐私保护指引**。
必须如实勾选收集的信息类型，并写清用途和保存期限。

> 加密存储也不能不申报。这是很多人被驳回的地方。

### 陷阱 4：抓取教务系统 = 潜在的第三方权益问题

说实话：**这类小程序长期存在，但随时可能因为学校投诉被下架。**

技术上降低风险的做法：
- 只聚合**用户自己**的数据，不做任何批量/爬全网
- 不把"爬取教务系统"写进简介（如实描述用途即可，但不用渲染技术手段）
- 在小程序内放免责声明（`我的 → 关于` 里已经有了）
- 不要把服务公开到校外大规模传播 —— 量一大，学校网信办就会注意到

### 陷阱 5：教育类目无资质

见第一节决定 2。报「工具」，不要报「教育」。

## 十一、检查清单

发布前逐项确认：

- [ ] 小程序账号已注册，拿到 AppID

## 十二、审核/备案被驳回怎么办

**本项目真实遇到的两次驳回**（都是备案阶段，还没走到提审）：

| 修改字段 | 待完善原因 | 修改建议（原文） |
| --- | --- | --- |
| 小程序名称 | 小程序名称不符合要求、名称/服务内容/备注三者无关联 | 修改后重新提交 |
| 小程序备注 | 小程序备注不符合要求、不符合个人小程序备案要求 | 转为符合个人性质的备注，或删减 |

另有**一次电话沟通**：审核方认为名字像机构，要求提供**学校那边的证明文件**。
—— 这是"个人主体 + 机构性质名称"的典型冲突，**不是补材料能解决的**，正解是改成个人性质的名。

常见驳回理由和应对：

| 驳回理由 | 应对 |
| --- | --- |
| "功能不完整/无法使用" | 见陷阱 1 —— 让未绑定用户也有内容看 |
| "涉及教育信息服务，需提供资质" | 改类目到「工具」，弱化教育表述 |
| "名称涉嫌侵权/易被误解" | 改中性名 |
| **"名称、服务内容、备注三者无关联"** | 名字里留一个能指向用途的字（如 `粥/周`、`历`），并在备案备注里**明写这层关联** |
| **"不符合个人小程序备案要求"** | 按第三节 **3.1 备案备注** 重写备注，删掉一切企业/机构/经营性表述 |
| **电话要求补学校证明** | 名字去机构化（去掉"校园"等词）；个人主体**拿不出也不该拿**这种证明 |
| "缺少用户隐私保护指引" | 后台补配置 |
| "服务类目与实际内容不符" | 类目改对，或砍掉不匹配的功能 |
| "需提供 ICP 备案" | 走完第三节 |

> ★ **优先顺序很重要**：名称和备注要先过，**备案通过后才轮得到提交审核**。
> 名字不确定就别急着提，否则每轮都要等 1～20 个工作日。

每次驳回会告诉具体理由，改完可以重新提交，**不限次数**。
