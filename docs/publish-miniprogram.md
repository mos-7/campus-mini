# 发布微信小程序：完整流程

## 零、先说清楚哪部分我不能替你做

**我不能替你发布。** 这不是技术问题，是身份和法律问题：

| 步骤 | 为什么必须你本人 |
| --- | --- |
| 注册小程序账号 | 要你的**身份证 + 人脸识别**（或企业的营业执照 + 对公账户打款验证） |
| 登录微信开发者工具 | 要**你本人微信扫码**，二维码只在你手机上 |
| 小程序 ICP 备案 | 要你的主体信息、负责人身份证、手写签名 |
| 提交审核 | 审核通过后，**你**是内容的责任主体 |

所以任何"我直接帮你发"的说法都是不成立的 —— 中间那几步物理上就在你手机上。

**我能做、也已经做的**：把代码、配置、构建产物、部署脚本全部准备好，让你剩下的部分只有
"注册 → 扫码 → 点上传 → 点提交"。这份文档就是那份操作手册。

预计你自己动手的总时间：**注册 30 分钟 + 备案等 1～20 个工作日 + 上传审核 1～7 天**。

---

## 一、先决定两件事（决定后面全部流程）

### 决定 1：个人主体 还是 企业/组织主体？

|  | 个人主体 | 企业/组织主体 |
| --- | --- | --- |
| 注册材料 | 身份证 + 手机号 + 邮箱 | 营业执照/事业单位法人证 + 对公账户 |
| 可选类目 | **受限** | 宽 |
| 微信支付 | ❌ 开不了 | ✅ |
| 参考截图里那个"投喂奶娃"打赏 | ❌ 做不了 | ✅ |
| 小程序备案 | 需要 | 需要 |
| 审核严格度 | 略严 | 正常 |

**对校园工具类，个人主体够用。** 代价就是打赏功能和部分类目。

> 如果你只是想先跑起来给自己和同学用，个人主体是最快的路。

### 决定 2：类目报什么

**推荐：`工具` → `效率` 或 `信息查询`。**

⚠️ **不要报「教育」类目。** 教育类目下的子类（在线教育、教育信息服务等）都需要资质，
个人主体直接过不了，企业主体要 ICP 许可证或办学许可。

### 决定 3：名称

**不要在小程序名称里放学校名字。**

- 含"XX大学/学院"→ 需要学校授权书，个人主体**必被驳回**
- 建议用通用名：`校园盒子`、`课表盒子`、`同学你好` 这类

名称审核是独立的一道，和类目审核分开，被驳了可以改名重申。

---

## 二、注册小程序账号

1. 打开 https://mp.weixin.qq.com → 右上角「立即注册」→ 选「小程序」
2. 填一个**没注册过公众号/小程序的邮箱**（QQ 邮箱最方便）
3. 去邮箱点激活链接
4. 选主体类型：
   - **个人**：填身份证 + 手机号 → 用**本人微信**扫码做人脸核验
   - **企业**：填营业执照 → 对公账户打款验证（几分钱）或法人扫脸
5. 注册完成后，在 **设置 → 基本设置** 里能看到 **AppID**，把它记下来

> AppID 形如 `wx1234567890abcdef`。这个填到 `miniprogram/project.config.json` 的 `appid` 字段。

---

## 三、小程序 ICP 备案（必须，不能跳过）

**2023 年 9 月起，新注册的小程序必须完成备案才能发布。** 没有备案，代码传上去了也没法提交审核。

1. mp 后台 → **设置 → 基本设置 → 小程序备案** → 开始备案
2. 填写：
   - 主体信息（自动带入注册时的）
   - **服务内容类型**：选「工具类」下最贴近的（如"效率工具"）
   - 负责人信息 + 身份证正反面 + **手写签名照**
   - 应急联系人
3. 提交后：微信初审（1～3 天）→ 提交通信管理局（1～20 个工作日，各省不同）
4. 通过后会拿到备案号，需在小程序内可查（一般放在「关于」页）

> **注意**：备案要求服务内容与实际功能一致。备案写"效率工具"但小程序里全是教育内容，
> 复查时可能被注销备案。

---

## 四、本地跑通（这步我已经替你做好了）

后端已经在跑，见文末「当前运行状态」。小程序端：

1. 下载安装 **微信开发者工具**：https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html
2. 打开 → 用**你注册小程序的微信**扫码登录
3. 「导入项目」→ 目录选 `campus-mini/miniprogram`
4. AppID 填你第二步拿到的
5. 后端地址确认：`miniprogram/utils/api.js` 里 `USE_CLOUD = false`（本地联调模式）
6. 开发者工具右上角「详情」→「本地设置」→ 勾上 **不校验合法域名**

这时候应该能看到首页、课表（有演示数据）、工具、我的四个 tab。

---

## 五、部署后端到微信云托管

**这一步必须在"上传代码"之前做完**，否则审核时小程序拿不到数据。

完整步骤见 [`deploy-cloudrun.md`](deploy-cloudrun.md)。关键几点：

```powershell
# 打包（在 campus-mini 目录下）
Compress-Archive -Path server\build.gradle, server\settings.gradle, server\Dockerfile, server\src `
                 -DestinationPath server.zip -Force
```

然后云托管控制台 → 服务 `campus-api` → 新建版本 → 上传 `server.zip` → 部署。

**部署后必做的三件事**：

1. **环境变量 `CAMPUS_WECHAT_MOCK_ENABLED=false`**
   ⚠️ 不关掉的话，任何人 POST 一个 `{"openid":"别人的openid"}` 就能拿到那个人的 token ——
   这是**严重安全漏洞**。
2. **最小实例副本设为 1** —— 否则异步同步任务会被缩容杀掉。
3. 服务日志里核对云托管注入 openid 的**请求头名字**，不是 `x-wx-openid` 就改
   `CAMPUS_WECHAT_OPENID_HEADER`。

部署好了以后，改 `miniprogram/utils/api.js`：

```js
const USE_CLOUD = true;
const CLOUD_ENV = '你的环境ID';
const CLOUD_SERVICE = 'campus-api';
```

---

## 六、配置服务器域名（免了）

**不用配。** 这是选云托管的最大好处 —— `callContainer` 不走 `wx.request` 的域名白名单：

> 小程序/公众号可使用 `CallContainer`，无需域名，因此不需要在 mp 管理后台配置服务器域名，
> 从而一开始就无需申请域名，也无需备案。
> —— [微信云托管开发常识](https://developers.weixin.qq.com/miniprogram/dev/wxcloudservice/wxcloudrun/src/guide/debug/know.html)

---

## 七、上传代码（需要你扫码）

1. 微信开发者工具 → 右上角 **「上传」** 按钮
2. 填**版本号**（如 `0.1.0`）和**项目备注**（如 `首个版本：课表 + 今日课程`）
3. 确定 → 代码上传到 mp 后台的「开发版本」

---

## 八、提交审核

1. 登录 https://mp.weixin.qq.com → **管理 → 版本管理**
2. 找到刚上传的「开发版本」→ 点 **「提交审核」**
3. 填写：
   - **功能页面**：至少要填首页和课表页
   - **测试账号**：⚠️ 见下面「审核陷阱」第 1 条
   - **审核备注**：写清楚怎么用。建议如实写：
     > 本小程序用于聚合用户本人的校园信息（课表）。需绑定用户自己的学校账号后才能展示
     > 完整课表；未绑定时显示引导页。不涉及任何课程学习进度操作。
4. 提交 → 审核 **1～7 天**

---

## 九、发布

审核通过后 → mp 后台「版本管理」→ **「全量发布」**。

发布后可以用「体验版」先给同学试：版本管理 → 开发版本 → 设为体验版，
把体验二维码发给他们（无需审核）。

## 十、⚠️ 这类小程序的高危陷阱

**这一节是本文档最重要的部分。** 校园信息聚合类小程序有特定的踩坑点：

### 陷阱 1：审核员看不到内容 → 被判"功能不完整"

小程序靠微信 openid 登录，**没法给审核员一个"测试账号"** —— 他打开就是新用户，
如果新用户看到的是空白页，大概率被驳回。

**对策（二选一）**：
- **A（推荐）**：让未绑定的用户也能看到一份**明确标注为"示例"**的课表，
  引导他绑定。这样审核员一打开就有内容，同时不骗真实用户。
  > 当前代码里 `campus.demo-data=true` 灌的是 `demo` 账号的数据，**新用户看不到**。
  > 要做到 A，需要改成"用户未绑定时，返回演示课表并带 `demo:true` 标记"。
  > 这是我建议你下一步加的功能，改动不大。
- **B**：在审核备注里详细说明"需绑定校园账号后才能看到课表，这是设计如此"，
  并上传截图。成功率低于 A。

### 陷阱 2：名称/简介暗示学校官方

- 名称含学校名 → 需要授权书
- 简介写"XX大学官方课表" → 被驳回，甚至被学校投诉
- 用「校园盒子」这类中性名 + 简介写"个人开发的校园信息聚合工具"

### 陷阱 3：用户隐私保护指引（强制）

**2023 年 9 月起，小程序必须在 mp 后台配置《用户隐私保护指引》**，
否则调用涉及用户信息的接口会被拦截。

你这个项目**收集了什么**：
- 微信 openid（用于识别用户）
- 你学校的账号密码（用于登录教务系统，AES-GCM 加密存储）

后台配置路径：**设置 → 服务内容声明 → 用户隐私保护指引**。
必须如实勾选收集的信息类型，并写清用途和保存期限。

> 加密存储也不能不申报。这是很多人被驳回的地方。

### 陷阱 4：抓取教务系统 = 潜在的第三方权益问题

说实话：**这类小程序长期存在，但随时可能因为学校投诉被下架。**

技术上降低风险的做法：
- 只聚合**用户自己**的数据，不做任何批量/爬全网
- 不把"爬取教务系统"写进简介（如实描述用途即可，但不用渲染技术手段）
- 在小程序内放免责声明（`我的 → 关于` 里已经有了）
- 不要把服务公开到校外大规模传播 —— 量一大，学校网信办就会注意到

### 陷阱 5：教育类目无资质

见第一节决定 2。报「工具」，不要报「教育」。

## 十一、检查清单

发布前逐项确认：

- [ ] 小程序账号已注册，拿到 AppID
- [ ] **小程序备案已通过**（没有备案无法提交审核）
- [ ] 类目报的是「工具 - 效率/信息查询」
- [ ] 名称不含学校名
- [ ] 《用户隐私保护指引》已在后台配置
- [ ] 后端已部署到云托管，`/api/health` 可访问
- [ ] `CAMPUS_WECHAT_MOCK_ENABLED=false` ★ 安全
- [ ] `CAMPUS_MASTER_KEY` / `CAMPUS_JWT_SECRET` 已配置 ★ 安全
- [ ] 云托管最小实例副本 = 1
- [ ] `api.js` 里 `USE_CLOUD=true`、`CLOUD_ENV` 已填
- [ ] 首页「关于」页能看到免责声明
- [ ] 审核备注写清楚使用方式
- [ ] 检查过一次真机预览（不是只在开发者工具里看）

## 十二、审核被驳回怎么办

常见驳回理由和应对：

| 驳回理由 | 应对 |
| --- | --- |
| "功能不完整/无法使用" | 见陷阱 1 —— 让未绑定用户也有内容看 |
| "涉及教育信息服务，需提供资质" | 改类目到「工具」，弱化教育表述 |
| "名称涉嫌侵权/易被误解" | 改中性名 |
| "缺少用户隐私保护指引" | 后台补配置 |
| "服务类目与实际内容不符" | 类目改对，或砍掉不匹配的功能 |
| "需提供 ICP 备案" | 走完第三节 |

每次驳回会告诉具体理由，改完可以重新提交，**不限次数**。
